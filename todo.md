# Задание

Вам необходимо создать простой RESTful API с базовыми CRUD-операциями для персональной блог-платформы.

CRUD означает:

* Create — создание;
* Read — чтение;
* Update — обновление;
* Delete — удаление.

## Цели

Цели этого проекта:

* понять, что такое RESTful API, включая основные рекомендации, соглашения и лучшие практики;
* научиться создавать RESTful API;
* изучить распространённые HTTP-методы: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`;
* изучить HTTP-коды состояния и обработку ошибок в API;
* научиться выполнять CRUD-операции через API;
* научиться работать с базами данных.

# Требования

Необходимо создать RESTful API для персональной блог-платформы.

API должен позволять пользователям выполнять следующие операции:

* создавать новую публикацию;
* обновлять существующую публикацию;
* удалять существующую публикацию;
* получать одну публикацию;
* получать все публикации;
* фильтровать публикации по поисковому запросу.

Ниже приведены подробности для каждой API-операции.

# Создание публикации

Создание новой публикации должно выполняться с помощью метода `POST`.

```http
POST /posts
```

Тело запроса:

```json
{
  "title": "My First Blog Post",
  "content": "This is the content of my first blog post.",
  "category": "Technology",
  "tags": ["Tech", "Programming"]
}
```

Каждая публикация должна содержать следующие поля:

```json
{
  "title": "My First Blog Post",
  "content": "This is the content of my first blog post.",
  "category": "Technology",
  "tags": ["Tech", "Programming"]
}
```

Эндпоинт должен валидировать тело запроса.

В случае успешного создания публикации он должен возвращать HTTP-статус:

```text
201 Created
```

и созданную публикацию:

```json
{
  "id": 1,
  "title": "My First Blog Post",
  "content": "This is the content of my first blog post.",
  "category": "Technology",
  "tags": ["Tech", "Programming"],
  "createdAt": "2021-09-01T12:00:00Z",
  "updatedAt": "2021-09-01T12:00:00Z"
}
```

В случае ошибок валидации эндпоинт должен возвращать:

```text
400 Bad Request
```

вместе с сообщениями об ошибках.

# Обновление публикации

Обновление существующей публикации должно выполняться с помощью метода `PUT`.

```http
PUT /posts/1
```

Тело запроса:

```json
{
  "title": "My Updated Blog Post",
  "content": "This is the updated content of my first blog post.",
  "category": "Technology",
  "tags": ["Tech", "Programming"]
}
```

Эндпоинт должен валидировать тело запроса.

В случае успешного обновления он должен возвращать:

```text
200 OK
```

и обновлённую публикацию:

```json
{
  "id": 1,
  "title": "My Updated Blog Post",
  "content": "This is the updated content of my first blog post.",
  "category": "Technology",
  "tags": ["Tech", "Programming"],
  "createdAt": "2021-09-01T12:00:00Z",
  "updatedAt": "2021-09-01T12:30:00Z"
}
```

В случае ошибок валидации эндпоинт должен возвращать:

```text
400 Bad Request
```

вместе с сообщениями об ошибках.

Если публикация с указанным идентификатором не найдена, эндпоинт должен возвращать:

```text
404 Not Found
```

# Удаление публикации

Удаление существующей публикации должно выполняться с помощью метода `DELETE`.

```http
DELETE /posts/1
```

Если публикация была успешно удалена, эндпоинт должен возвращать:

```text
204 No Content
```

Тело ответа в этом случае отсутствует.

Если публикация не найдена, эндпоинт должен возвращать:

```text
404 Not Found
```

# Получение одной публикации

Получение одной публикации должно выполняться с помощью метода `GET`.

```http
GET /posts/1
```

Если публикация найдена, эндпоинт должен возвращать:

```text
200 OK
```

и данные публикации:

```json
{
  "id": 1,
  "title": "My First Blog Post",
  "content": "This is the content of my first blog post.",
  "category": "Technology",
  "tags": ["Tech", "Programming"],
  "createdAt": "2021-09-01T12:00:00Z",
  "updatedAt": "2021-09-01T12:00:00Z"
}
```

Если публикация не найдена, эндпоинт должен возвращать:

```text
404 Not Found
```

# Получение всех публикаций

Получение всех публикаций должно выполняться с помощью метода `GET`.

```http
GET /posts
```

Эндпоинт должен возвращать:

```text
200 OK
```

и массив публикаций:

```json
[
  {
    "id": 1,
    "title": "My First Blog Post",
    "content": "This is the content of my first blog post.",
    "category": "Technology",
    "tags": ["Tech", "Programming"],
    "createdAt": "2021-09-01T12:00:00Z",
    "updatedAt": "2021-09-01T12:00:00Z"
  },
  {
    "id": 2,
    "title": "My Second Blog Post",
    "content": "This is the content of my second blog post.",
    "category": "Technology",
    "tags": ["Tech", "Programming"],
    "createdAt": "2021-09-01T12:30:00Z",
    "updatedAt": "2021-09-01T12:30:00Z"
  }
]
```

Для этого проекта не требуется реализовывать:

* пагинацию;
* аутентификацию;
* авторизацию.

Можно сосредоточиться на основной функциональности API.

# Поиск публикаций

При получении списка публикаций пользователь также должен иметь возможность фильтровать их с помощью поискового запроса.

Необходимо выполнять поиск по частичному совпадению в следующих полях:

* `title`;
* `content`;
* `category`.

Пример запроса:

```http
GET /posts?term=tech
```

Запрос должен вернуть все публикации, у которых строка `"tech"` встречается в заголовке, содержимом или категории.

Если используется SQL-база данных, можно применить простой SQL-запрос с оператором `LIKE` или `ILIKE`.

Для NoSQL-базы данных можно использовать аналогичный механизм поиска, поддерживаемый выбранной СУБД.

* JavaScript — Node.js и Express.js;
